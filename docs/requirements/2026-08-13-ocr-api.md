# OCR API 需求文档

## 目标

提供本地验证、可迁移到内网服务器的 OCR HTTP API，供 Java 等外部系统调用。

当前识别范围：

- 居民身份证图片
- 营业执照图片

Python 服务只负责调用 PaddleOCR-VL-1.6 并返回模型原始 JSON。身份证字段、营业执照字段和最终业务响应由 Java 调用方负责解析和封装。

## 技术方案

- FastAPI + Uvicorn
- PaddleOCR-VL-1.6
- GPU/CPU 由 `OCR_DEVICE` 配置
- 本地 Streamlit Demo 用于上传图片和查看原始 JSON
- 不做鉴权、数据库、历史记录或业务字段提取

## 接口

- `GET /api/v1/health`
- `POST /api/v1/ocr/id-card`
- `POST /api/v1/ocr/business-license`

## 请求体

两个 OCR 接口使用相同 JSON 请求体：

```json
{
  "orderNo": "202304031918463633573",
  "imageBase64": "",
  "imageUrl": ""
}
```

规则：

- `orderNo` 可选，仅用于错误日志和失败响应追踪；未提供时由服务端生成。
- `imageBase64` 和 `imageUrl` 至少提供一个。
- 两者同时提供时优先使用 `imageBase64`。
- `imageBase64` 支持纯 Base64 或 data URL 前缀。
- `imageUrl` 只允许公网 `http` / `https` 图片 URL。
- 图片只在内存中处理，不保存上传内容或识别记录。

## 成功响应

成功时直接返回 PaddleOCR-VL 原始 JSON，不增加 `msg`、`success`、`code`、`data`、`info` 或 `content` 外层结构。

实际字段以当前 PaddleOCR-VL-1.6 返回结果为准，常见结构如下：

```json
{
  "res": {
    "input_path": null,
    "page_index": null,
    "page_count": null,
    "width": 640,
    "height": 640,
    "model_settings": {},
    "parsing_res_list": [],
    "doc_preprocessor_res": {},
    "layout_det_res": {}
  }
}
```

单张图片通常返回一个 JSON 对象；如果模型返回多页结果，服务会返回 JSON 数组，每个元素对应一个原始结果对象。Python 不修改模型字段名、不脱敏、不提取业务字段。

Java 调用方可以根据 `res.parsing_res_list`、`res.doc_preprocessor_res`、`res.layout_det_res` 等字段自行实现身份证和营业执照的业务映射。

## 失败响应

参数错误：

```json
{
  "msg": "参数错误",
  "success": false,
  "code": 400,
  "data": {
    "result": 1,
    "orderNo": "202304031923431170794"
  }
}
```

OCR 识别异常：

```json
{
  "msg": "OCR识别异常",
  "success": false,
  "code": 1001,
  "data": {
    "result": 1,
    "orderNo": "202304031923431170794"
  }
}
```

规则：

- HTTP 始终返回 200，业务状态由响应 JSON 的 `success`、`code` 和 `data.result` 表示。
- 参数错误包括缺少图片来源、非法 Base64、非法 URL、非 `http/https` URL、图片不可解码或超过限制。
- OCR 识别异常包括图片 URL 下载失败、下载超时、PaddleOCR-VL 推理异常或原始结果转换失败。
- 响应不暴露内部异常堆栈、依赖版本、文件路径或网络细节。

## 公网 URL 安全边界

- 仅允许 `http`、`https`。
- 禁止 localhost、私有地址、回环地址、链路本地地址、保留地址和多播地址。
- 每次重定向均重新校验目标 URL。
- 下载连接和读取超时均限制为 10 秒。
- 限制图片最大大小为 10 MiB。
- 限制响应 Content-Type 为常见图片类型，且必须使用 Pillow 二次验证真实图片内容。

## 非目标

- 当前版本不做鉴权、限流、数据库或历史记录。
- 当前版本不做身份证/营业执照业务字段提取。
- 当前版本图片接口不接收 PDF、批处理或 multipart 文件上传。
- 当前版本不保存图片和识别结果。
