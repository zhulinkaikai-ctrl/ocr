# OCR API 需求文档

## 目标

提供本地验证、可迁移到内网服务器的 OCR HTTP API，供外部业务系统调用。

支持两类证件：

- 身份证正面
- 营业执照

## 技术方案

- FastAPI + Uvicorn
- 复用现有 PaddleOCR GPU 适配器
- 复用现有身份证字段抽取能力
- 增加营业执照字段规则抽取
- Streamlit Demo 保留，用于人工验证

## 接口

- `GET /api/v1/health`
- `POST /api/v1/ocr/id-card`
- `POST /api/v1/ocr/business-license`

## 请求体

两个 OCR 接口使用相同 JSON 请求体：

```json
{
  "orderNo": "202304031918463633573",
  "imageBase64": "",
  "imageUrl": ""
}
```

规则：

- `orderNo` 可选；未提供时由服务端生成。
- `imageBase64` 和 `imageUrl` 至少提供一个。
- 两者同时提供时优先使用 `imageBase64`。
- `imageBase64` 支持纯 Base64 或 data URL 前缀。
- `imageUrl` 只允许公网 `http` / `https` URL。
- 图片只在内存中处理，不保存上传内容或识别记录。

## 身份证正面成功响应

```json
{
  "msg": "成功",
  "success": true,
  "code": 200,
  "data": {
    "result": 0,
    "side": "front",
    "orderNo": "202304031918463633573",
    "info": {
      "number": "330*********1011",
      "address": "浙江省*****651号",
      "month": "8",
      "nation": "汉",
      "year": "1981",
      "sex": "男",
      "name": "张*江",
      "day": "16"
    }
  }
}
```

身份证第一版仅支持正面，`side` 固定为 `front`。

## 营业执照成功响应

```json
{
  "msg": "成功",
  "success": true,
  "code": 200,
  "data": {
    "result": 0,
    "orderNo": "202406301147521497006",
    "content": {
      "enterprise_type": "个体工商户",
      "address": "江西省****御景铭城",
      "registration_capital": "XXX",
      "op_to": "XXX",
      "org_form": "个人经营",
      "op_scope": "许可项目:餐饮服务。",
      "establishing_date": "2024-04-19",
      "registration_code": "",
      "op_from": "",
      "credit_code": "9243XXXXXX49E",
      "lR_name": "赵***",
      "op_period": "",
      "enterprise_name": "上海市****店",
      "is_copy": 0
    }
  }
}
```

字段规则：

- `credit_code`：统一社会信用代码。
- `registration_code`：注册号；未识别时为空字符串。
- `enterprise_name`：企业名称。
- `enterprise_type`：企业类型。
- `lR_name`：法定代表人或经营者姓名。
- `registration_capital`：注册资本。
- `establishing_date`：成立日期，优先返回 `YYYY-MM-DD`；无法解析时返回 OCR 原始文本。
- `op_period`：经营日期起止文本，格式优先规范为 `YYYY年MM月DD日 至 YYYY年MM月DD日`。
- `op_from`、`op_to`：经营日期起止，优先返回 `YYYY-MM-DD`；无法解析时为空字符串。
- `address`：地址或经营场所。
- `op_scope`：经营范围。
- `org_form`：组成形式。
- `is_copy`：副本标记；第一版默认 `0`。

营业执照字段应尽量提取，无法识别的字段返回空字符串，不省略 key。

## 失败响应

参数错误：

```json
{
  "msg": "参数错误",
  "success": false,
  "code": 400,
  "data": {
    "result": 1,
    "orderNo": "202304031923431170794"
  }
}
```

OCR 识别异常：

```json
{
  "msg": "OCR识别异常",
  "success": false,
  "code": 1001,
  "data": {
    "result": 1,
    "orderNo": "202304031923431170794"
  }
}
```

规则：

- HTTP 始终返回 200，业务状态由响应 JSON 的 `success`、`code` 和 `data.result` 表示。
- 参数错误包括缺少图片来源、非法 Base64、非法 URL、非 `http/https` URL、图片不可解码或超过限制。
- OCR 识别异常包括图片 URL 下载失败、下载超时、PaddleOCR 推理异常或目标证件关键字段未识别。
- 响应不暴露内部异常堆栈、依赖版本、文件路径或网络细节。

## 公网 URL 安全边界

- 仅允许 `http`、`https`。
- 禁止 localhost、私有地址、回环地址、链路本地地址、保留地址和多播地址。
- 每次重定向均重新校验目标 URL。
- 下载连接和读取超时均限制为 10 秒。
- 限制图片最大大小为 10 MiB。
- 限制响应 Content-Type 为常见图片类型，且必须使用 Pillow 二次验证真实图片内容。

## 非目标

- 第一版不做鉴权、限流、数据库或历史记录。
- 第一版不支持身份证反面、PDF、批处理和文件上传。
- 第一版不保存图片和识别结果。
